# Slice 5 — What the person sees: working line, result block, log with steps

Parent plan: `PLAN.md` (approved) § Подход 6 — the owner's rule: **how the
model thought matters only when debugging**. So: no steps in the chat, one
line while waiting, steps in the journal. Order: **fifth**; needs slice 3
(`steps[]`, `usage`) and slice 1 (fact line format).

## WHAT and WHY

The librarian may take several seconds and several server calls. The person
must see that a delegation is running and that it finished — without the chat
filling up with the librarian's tool trail. Three existing surfaces, no new
ones:

1. **pi's own "Working…" line** while the delegation runs, overwritten with
   our text via `ctx.ui.setWorkingMessage(text)` and restored afterwards.
2. **The tool result block** of `hindsight_recall` in the chat: the answer and
   the facts, never the steps.
3. **`/mem` → Log**: one entry per delegation with `steps[]` and cost, expanded
   on `Enter`.

## Specification

### Requirement: The working line during a delegation

`hindsight_recall.execute` SHALL call `ctx.ui.setWorkingMessage(
"🧠 recall · «<question>» · step <n>/<max>")` before the loop and after every
step, and SHALL call `ctx.ui.setWorkingMessage()` (no argument) in a
`finally` — so the line is restored on success, on step limit, on model
error **and on abort**. The question is clipped with `…` so the line stays
under 80 columns.

#### Scenario: Restored on every exit

- **WHEN** the delegation ends by answer / limit / error / abort (four runs)
- **THEN** in each run the spy records `setWorkingMessage` called with
  `step 0/4` first, then once per step, then exactly once with no argument as
  the LAST call

### Requirement: The result block shows the answer, not the trail

`renderResult` SHALL produce, collapsed:

```text
🧠 recall · «<question>» · <scope>   ✓ <steps> steps · <facts> facts · <secs>s
```

and expanded: that line, the summary paragraph, a blank line, then the fact
lines in slice 1's format. Step limit replaces `✓ …` with
`⚠ step limit (<max>) · <secs>s`; error with `✗ <error>`. Nothing about
individual tool calls appears in either view.

#### Scenario: Collapsed and expanded, no ANSI

- **WHEN** a result with 3 steps, 2 facts and 2.4 s is rendered with
  `expanded=false` and `expanded=true`
- **THEN** the collapsed output is exactly one line matching the shape above,
  and the expanded output contains no line starting with `↙` or naming
  `bank_search` / `bank_reflect` / `bank_document`

### Requirement: The journal carries the steps and the cost

The `recall` log entry written by the tool SHALL carry `steps: Array<{ tool,
bank, arg, outcome, ms }>` and `cost?: number` (USD, summed from `usage` with
the luna prices; `undefined` when the provider returned no usage).

`/mem` → Log row: `↙ <hh:mm> recall  <injected>/<found>  <steps> steps · $<cost>  <query>`
(`· $—` when cost is undefined). `Enter` expands to one line per step:

```text
↙ project  bank_reflect  «<question>»   → draft, <n> chars
↙ project  bank_search   "<query>"      → <n> facts
✓ answer                                → <n> facts kept
```

#### Scenario: Row and expansion

- **WHEN** an entry with 3 steps and cost 0.004 is in the log and the Log tab
  is opened, the row selected and `Enter` pressed
- **THEN** the row reads `3 steps · $0.004` and the detail shows exactly three
  step lines in the shape above

### Requirement: Nothing else lights up

No `notify`, no widget state change beyond today's `↙ N` after the tool
returns, no footer/header text, no second message in the context.
